3. Leer el usuario de la sesión

Inyecta CurrentUserService (paquete org.jala.edu.core.contract) en el controlador de la pantalla y pasa el id al caso de uso. Tu módulo no depende de user-module: solo de core-module.

❌ Antes

@Component
@Scope(ConfigurableBeanFactory.SCOPE_PROTOTYPE)
@RequiredArgsConstructor
public class NewCartController {

    private static final UUID CURRENT_CUSTOMER = SampleUsers.CUSTOMER;   // ❌ usuario fijo

    private final AddProductToCartUseCase addProductToCart;
    ...
    () -> addProductToCart.execute(CURRENT_CUSTOMER, product.productId(), quantity)

✅ Después

@Component
@Scope(ConfigurableBeanFactory.SCOPE_PROTOTYPE)
@RequiredArgsConstructor
public class NewCartController {

    private final CurrentUserService currentUserService;               // ✅ contrato de core
    private final AddProductToCartUseCase addProductToCart;
    ...
    UUID customerId = currentUserService.currentUser().id();          // quién inició sesión
    () -> addProductToCart.execute(customerId, product.productId(), quantity)

Lee currentUser() en el momento de la acción (al pulsar el botón), no en una constante. Si nadie inició sesión lanza NotAuthenticatedException; findCurrentUser() devuelve un Optional si prefieres decidir tú.

4. Permisos y pruebas

Los permisos siguen en el caso de uso

CurrentUserService dice quién es; UserService.isActiveWithRole dice si puede (D-07). No quites esa validación: así un usuario desactivado no opera aunque tenga sesión.

// AddProductToCartUseCase NO cambia: sigue validando el permiso con UserService (D-07)
if (!users.isActiveWithRole(customerId, UserRole.CUSTOMER)) {
    throw new DomainException("User not authorized for this operation");
}

Pruebas sin user-module

// En las pruebas no hace falta user-module: CurrentUserService tiene un solo método
CurrentUserService asCustomer = () -> Optional.of(
        new CurrentUser(SampleUsers.CUSTOMER, UserRole.CUSTOMER, "Sample Customer"));

CurrentUserService nobody = Optional::empty;   // currentUser() lanza NotAuthenticatedException

Sin login (pruebas con Spring o un módulo sin user-module), core responde con un usuario de ejemplo del rol en delivery.sample-user (CUSTOMER por defecto; variable DELIVERY_SAMPLE_USER=COURIER).

Al pulsar Sign out se publica SignOutEvent. Si tu módulo guarda algo por usuario en memoria, puedes escucharlo:

// Opcional: limpiar datos de la sesión al cerrar sesión (por ejemplo, un carrito en memoria)
@EventListener(SignOutEvent.class)
public void clearOnSignOut() {
    cart.clear();
}

6. Base de datos

Con -Pjpa la aplicación usa MySQL. Hoy solo user-module guarda en la base (tabla users, migraciones en db/migration/user); tu módulo sigue en memoria hasta que tenga su adaptador JPA, y el log lo avisa.

cd delivery-system
docker compose up -d              # MySQL en Docker
./mvnw javafx:run -Pjpa           # o DELIVERY_PERSISTENCE_TYPE=jpa ./mvnw javafx:run

Cuando tu equipo agregue persistencia (según lo que se acuerde en la reunión de Scrum Masters): entidad y adaptador con @ConditionalOnJpaPersistence, migraciones en db/migration/<tu-modulo>/V<yyyyMMddHHmm>__…sql y sin claves foráneas a users: guarda el UUID del usuario y valídalo con UserService. Modelo a seguir: UserPersistenceAdapter y su prueba con H2.
