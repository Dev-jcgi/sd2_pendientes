4. Receta: una historia de punta a punta

Ejemplo real: #57 "Proteger al último administrador y desactivar en lugar de borrar". Cada paso es un commit pequeño que compila solo.

Dominio: la regla vive en el modelo

User.java · PhoneNumber.java. Tu modelo extiende BaseModel<ID> de core (id, createdAt, updatedAt, touch()). Un value object es un record que valida en su constructor y lanza DomainException.

// domain/model/User.java — la regla vive en el modelo
public void activate() {
    this.status = UserStatus.ACTIVE;
    touch();                       // BaseModel actualiza updatedAt
}

public void deactivate() {
    this.status = UserStatus.INACTIVE;
    touch();
}

// domain/model/PhoneNumber.java — value object: valida en su constructor
public record PhoneNumber(String value) {
    private static final Pattern PATTERN = Pattern.compile("^\\+[1-9]\\d{1,14}$");

    public PhoneNumber {
        if (value == null || !PATTERN.matcher(value.strip()).matches()) {
            throw new DomainException("Invalid phone number: " + value);
        }
        value = value.strip();
    }
}

Puerto de salida: lo que la aplicación necesita guardar o consultar

UserRepositoryPort.java. Extiende CrudRepositoryPort de core y agrega solo las consultas que tus casos de uso usan.

// application/port/out/UserRepositoryPort.java
public interface UserRepositoryPort extends CrudRepositoryPort<User, UserId> {   // save, findById, findAll… de core

    boolean existsByEmail(Email email);

    long countActiveByRole(UserRole role);

    List<User> findByEmailContaining(String fragment);

    Optional<User> findByEmail(Email email);

Caso de uso: Java puro que orquesta

ChangeUserStatusUseCase.java. Implementa UseCase<Input, Output>; recibe los puertos por constructor; sin anotaciones de Spring. Si la operación necesita un rol, aquí se valida con UserService.isActiveWithRole.

// application/usecase/ChangeUserStatusUseCase.java — Java puro, sin anotaciones de Spring
public class ChangeUserStatusUseCase implements UseCase<ChangeUserStatusCommand, Void> {

    private final UserRepositoryPort userRepository;

    public ChangeUserStatusUseCase(UserRepositoryPort userRepository) {
        this.userRepository = userRepository;
    }

    @Override
    public Void execute(ChangeUserStatusCommand command) {
        UserId id = new UserId(command.id());
        User user = userRepository.findById(id).orElseThrow(() -> new UserNotFoundException(id));
        if (command.status() == user.getStatus()) {
            return null;
        }
        ActiveAdminRule.check(user, user.getRole(), command.status(), userRepository);   // nunca sin ADMIN activo
        if (command.status() == UserStatus.ACTIVE) {
            user.activate();
        } else {
            user.deactivate();
        }
        userRepository.save(user);
        return null;
    }
}

Adaptador en memoria (modo por defecto y fake de pruebas)

InMemoryUserRepositoryAdapter.java. Extiende InMemoryCrudRepository de core: solo implementas las consultas nuevas con stream().

// infrastructure/adapter/out/persistence/memory/InMemoryUserRepositoryAdapter.java
@Component
@ConditionalOnInMemoryPersistence
public class InMemoryUserRepositoryAdapter extends InMemoryCrudRepository<User, UserId> implements UserRepositoryPort {

    @Override
    public long countActiveByRole(UserRole role) {
        return stream().filter(user -> user.isActive() && user.getRole() == role).count();
    }

    @Override
    public Optional<User> findByEmail(Email email) {
        return stream().filter(user -> user.getEmail().equals(email)).findFirst();
    }
    // … existsByEmail y findByEmailContaining igual, con stream()
}

Pantalla: el controlador llama al caso de uso

ListUsersController.java. BackgroundTasks.run ejecuta fuera del hilo de JavaFX; ErrorMessages.of convierte la excepción del dominio en un mensaje.

// infrastructure/adapter/in/ui/ListUsersController.java
@FXML
void onToggleStatus() {
    User selected = usersTable.getSelectionModel().getSelectedItem();
    UserStatus newStatus = selected.isActive() ? UserStatus.INACTIVE : UserStatus.ACTIVE;
    BackgroundTasks.run(                                                    // fuera del hilo de JavaFX
            () -> changeUserStatusUseCase.execute(new ChangeUserStatusCommand(selected.getId().value(), newStatus)),
            done -> reload("User " + selected.fullName() + " updated."),
            error -> showMessage(ErrorMessages.of(error, "change the user status"), "error"));
}

Pruebas: patrón Arrange / Act / Assert

El adaptador en memoria es el fake del puerto: no hace falta Mockito ni Spring.

class ChangeUserStatusUseCaseTest {

    private final InMemoryUserRepositoryAdapter repository = new InMemoryUserRepositoryAdapter();
    private final ChangeUserStatusUseCase changeStatus = new ChangeUserStatusUseCase(repository);

    @Test
    void activatesAnInactiveUser() {
        // Arrange

        customer.deactivate();
        repository.save(customer);

        // Act

        // Assert

// Tu controlador (infrastructure/adapter/in/ui) — quién inició sesión
@Component
@Scope(ConfigurableBeanFactory.SCOPE_PROTOTYPE)
@RequiredArgsConstructor

                done -> refresh(),
                error -> showError(ErrorMessages.of(error, "add the product")));
    }

6. Implementar el contrato de tu módulo

Catálogo implementa CatalogService, Pedidos OrderService y Pagos PaymentService. Hoy ninguno está implementado: todos usan el fallback de core (lo dice el log con No module provides …). El patrón es el de UserServiceAdapter.java:

  1. Un caso de uso por operación del contrato (con sus pruebas).
  2. Un adaptador en infrastructure/adapter/in/contract que implementa el contrato y delega en esos casos de uso, traduciendo tus modelos a los records de core (ProductInfo, ReadyOrder, PaymentResult).
  3. Un @Bean del contrato en tu configuración. Al arrancar, el aviso del fallback desaparece.
// PLANTILLA (catálogo): infrastructure/adapter/in/contract/CatalogServiceAdapter.java
// Mismo patrón que UserServiceAdapter: el contrato de core delega en tus casos de uso.
public class CatalogServiceAdapter implements CatalogService {

    private final FindProductUseCase findProduct;
    private final ReserveStockUseCase reserveStock;
    // … un caso de uso por operación del contrato

    public CatalogServiceAdapter(FindProductUseCase findProduct, ReserveStockUseCase reserveStock /* … */) {
        this.findProduct = findProduct;
        this.reserveStock = reserveStock;
    }

    @Override
    public Optional<ProductInfo> findProduct(UUID productId) {
        return findProduct.execute(productId)                        // tu modelo de dominio
                .map(p -> new ProductInfo(p.getId().value(), p.getCommerceId(), p.getName(), p.getPrice()));
    }

    @Override
    public void reserveStock(UUID productId, int quantity) {
        reserveStock.execute(new ReserveStockCommand(productId, quantity));
    }
    // … isAvailable, releaseStock, findCommerceIdsByMerchant
}

// infrastructure/config/CatalogModuleConfiguration.java — al registrarlo, el fallback de core desaparece solo
@Bean
public CatalogService catalogService(FindProductUseCase findProduct, ReserveStockUseCase reserveStock /* … */) {
    return new CatalogServiceAdapter(findProduct, reserveStock /* … */);
}

Los nombres de los casos de uso de la plantilla son de ejemplo: usa los de tus historias. Un cambio en la firma del contrato se acuerda en la reunión de Scrum Masters.

7.2 Mapper y adaptador

UserPersistenceMapper.java · UserPersistenceAdapter.java

// UserPersistenceMapper.java — dominio ↔ entidad, en los dos sentidos
final class UserPersistenceMapper implements PersistenceMapper<User, UserId, UserJpaEntity, String> {

    @Override
    public UserJpaEntity toEntity(User user) {
        return new UserJpaEntity(toEntityId(user.getId()), user.getFirstName(), user.getLastName(),
                user.getEmail().value(), user.getPhoneNumber(), user.getRole().name(), user.getStatus().name(),
                user.getPasswordHash(), user.getCreatedAt(), user.getUpdatedAt());
    }

    @Override
    public User toDomain(UserJpaEntity entity) {
        return User.restore(UserId.of(entity.getId()), entity.getFirstName(), entity.getLastName(),
                new Email(entity.getEmail()), entity.getPhoneNumber(), UserRole.valueOf(entity.getRole()),
                UserStatus.valueOf(entity.getStatus()), entity.getPasswordHash(),
                entity.getCreatedAt(), entity.getUpdatedAt());
    }

    @Override
    public String toEntityId(UserId id) {
        return id.toString();
    }
}

// UserPersistenceAdapter.java — solo en modo jpa
@Component
@ConditionalOnJpaPersistence
class UserPersistenceAdapter extends JpaCrudRepositoryAdapter<User, UserId, UserJpaEntity, String>
        implements UserRepositoryPort {

    private final UserJpaRepository repository;
    private final UserPersistenceMapper mapper = new UserPersistenceMapper();

    UserPersistenceAdapter(UserJpaRepository repository) {
        super(repository, new UserPersistenceMapper());     // save, findById, findAll… ya resueltos
        this.repository = repository;
    }

    @Override
    public Optional<User> findByEmail(Email email) {
        return repository.findByEmail(email.value()).map(mapper::toDomain);
    }
    // … el resto de consultas del puerto
}

7.3 Migraciones Flyway

Carpeta src/main/resources/db/migration/<tu-modulo>/; nombre V<yyyyMMddHHmm>__descripcion.sql para que las versiones no choquen entre módulos. Nunca edites una migración ya aplicada: crea otra.

CREATE TABLE users

-- V202611020001__add_users_password_hash.sql — un cambio nuevo es una migración nueva
ALTER TABLE users
    ADD COLUMN password_hash VARCHAR(100) NULL;

Reglas para tus tablas

  • Prefijo del módulo: cat_, ord_, del_, pay_.
  • Sin claves foráneas entre módulos: guarda el UUID del usuario o del producto y valídalo con su contrato.
  • UUID como VARCHAR(36), enums como texto, fechas DATETIME(6) con created_at y updated_at.
  • Cuando tu adaptador JPA esté listo, pide quitar tu puerto de MissingJpaAdaptersAutoConfiguration.

11. Checklist de tu historia

  • Dominio con sus reglas y pruebas.
